# Ticket Tamer

AI-агент для автоматизации обработки писем технической поддержки.  
Проект разработан в рамках хакатона **ENIGMA HACK**.

---

## Пользовательский путь

1. **Клиент** отправляет письмо на адрес техподдержки.
2. Система автоматически получает письмо по **IMAP** и создаёт тикет в базе данных.
3. **AI-агент** анализирует письмо:
   - определяет категорию (техническая проблема, биллинг, общий вопрос, спам);
   - оценивает приоритет и тональность;
   - извлекает ключевые сущности (номер заказа, название продукта и т. д.).
4. Агент ищет релевантную статью в **базе знаний** и на её основе формирует черновик ответа.
5. Тикет со всеми данными (тема, статус, классификация, ответ) отображается в **веб-таблице**.
6. **Оператор техподдержки** просматривает таблицу, может отредактировать сгенерированный ответ или отправить его как есть.
7. Ответ отправляется клиенту по **SMTP**; тикет переводится в статус «Отвечен».
8. Оператор может отфильтровать тикеты по статусу/категории и **экспортировать** данные в CSV или XLSX.

### Компоненты

| Компонент | Технология | Описание |
|-----------|-----------|----------|
| Backend (API) | Python 3.10, FastAPI | REST API (`/api/v1/`) для тикетов, базы знаний, экспорта |
| AI-агент | Hugging Face Transformers (BERT/RoBERTa) | Классификация писем, извлечение сущностей, генерация ответов |
| База данных | PostgreSQL | Хранение тикетов, базы знаний, логов email-операций |
| Фронтенд | React + Vite + TypeScript | Веб-таблица с фильтрацией, сортировкой и экспортом |
| Email I/O | IMAP / SMTP (async) | Получение и отправка писем |
| Инфраструктура | Docker Compose | Оркестрация сервисов (backend, db, frontend) |

### Пайплайн AI-агента

Каждый шаг — отдельный модуль, который можно заменить или доработать независимо:

```
Входящее письмо
  → 1. Парсинг (subject, body, from, Message-ID)
  → 2. Классификация (категория, приоритет, тональность)
  → 3. Извлечение сущностей (NER)
  → 4. Поиск по базе знаний (category match → semantic search)
  → 5. Генерация ответа (шаблон KB + сущности)
  → 6. Сохранение в БД + отправка по SMTP
```

## Анализ рисков

| Риск | Вероятность | Последствие | Стратегия минимизации |
|------|:-----------:|:-----------:|----------------------|
| **Низкое качество классификации** на реальных данных | Высокая | Некорректные ответы клиентам | Использовать zero-shot classification; при confidence ниже порога — отправлять тикет на ручную проверку оператором, а не отвечать автоматически |
| **Долгая загрузка ML-моделей** при каждом запросе | Средняя | Задержки ответа > 10 сек | Загружать модели один раз при старте приложения (lifespan), кэшировать в Docker volume |
| **Проблемы с кодировкой email** (UTF-8, KOI8-R, Windows-1251) | Высокая | Нечитаемый текст, сломанный пайплайн | Использовать `email.policy.default` + автодетект кодировки через `charset_normalizer` |
| **Не успеваем реализовать фронтенд** | Средняя | Нет наглядной демонстрации | Начинать с минимальной таблицы (заготовка уже есть), наращивать фичи итеративно |
| **Docker не работает на площадке** | Низкая | Невозможно развернуть сервисы | Иметь fallback: `requirements.txt` + локальный PostgreSQL для запуска без Docker |
| **Ограниченное время хакатона** | Высокая | Неполная реализация | Чёткий roadmap с приоритезацией: сначала MVP (приём → классификация → таблица), потом генерация ответов и отправка |

## Структура проекта

```
ticket-tamer/
├── app/                    # FastAPI backend
│   ├── main.py             # Точка входа, lifespan, middleware
│   ├── config.py           # Settings из .env
│   ├── database.py         # Async SQLAlchemy engine
│   ├── models/             # ORM-модели (Ticket, KnowledgeBase, EmailLog)
│   ├── schemas/            # Pydantic-схемы (request/response)
│   ├── routers/            # API endpoints (tickets, kb, export)
│   └── services/           # Бизнес-логика (ticket_service, kb_service, email_service)
├── agent/                  # AI-агент (изолирован от web-слоя)
│   ├── pipeline.py         # Оркестратор: receive → classify → lookup → draft
│   ├── classifier.py       # Классификация (категория, приоритет, тональность)
│   ├── entity_extractor.py # NER — извлечение сущностей
│   ├── kb_lookup.py        # Поиск по базе знаний
│   ├── response_generator.py # Генерация ответа
│   └── models/loader.py    # Singleton-загрузка ML-моделей
├── frontend/               # React + Vite + TypeScript
│   └── src/
│       ├── components/     # TicketTable, ExportButtons
│       ├── api/client.ts   # HTTP-клиент к backend API
│       └── types/          # TypeScript типы
├── migrations/             # Alembic (миграции БД)
├── tests/                  # pytest
├── docker-compose.yml      # backend + postgres + frontend
├── Dockerfile              # Multi-stage build
└── requirements.txt
```

## Запуск

```bash
# Все сервисы через Docker
docker-compose up --build

# Или по отдельности:
# Backend
pip install -r requirements.txt
uvicorn app.main:app --reload

# Frontend
cd frontend && npm install && npm run dev
```
